# Data model

The authoritative definition is [`contracts/schema/001_initial.sql`](../contracts/schema/001_initial.sql).
This page explains the conventions and behavior around it.

## Conventions

- **Ids**: lowercase UUID v4 strings, generated by the client. Stable across export/import.
- **Timestamps**: UTC ISO-8601 with milliseconds, e.g. `2026-10-24T09:30:00.000Z`.
- **Due dates**: calendar dates `YYYY-MM-DD` (validated as real dates, e.g. `2026-02-30` is rejected).
- **Booleans**: `INTEGER` 0/1.
- **Connections**: `PRAGMA foreign_keys = ON`, WAL journal, 5 s busy timeout.
- **Migrations**: `PRAGMA user_version` holds the schema version. Each migration runs in one transaction.
  A client refuses to open a workspace with a newer version and does not modify it.

## Tables

### `pages`
| Column | Notes |
|---|---|
| `id` | primary key |
| `parent_id` | `NULL` = top-level page. FK → `pages(id)` **ON DELETE CASCADE** |
| `title` | may be empty (shown as "Untitled"); newlines stripped; ≤ 300 chars |
| `content_json` | page document, see below |
| `content_text` | plain-text projection written on every save (search + AI) |
| `sort_order` | order among siblings |
| `created_at`, `updated_at` | `updated_at` changes on every content/title/structure edit |
| `is_favorite`, `is_archived` | |

**Hierarchy rules**
- A page can't be its own parent (`CHECK`), and a trigger rejects moves that would create a cycle.
- **Delete** removes the page and its whole subtree. Tasks linked to any deleted page are **kept and
  unlinked** (`tasks.page_id` → `NULL`). The UI shows the number of subpages and linked tasks first.
- **Archive** applies to the page and all descendants; archived pages leave the sidebar, search and AI
  retrieval. **Restore** brings back the subtree; if the page's parent is still archived, it moves to the
  top level.

### `tasks`
| Column | Notes |
|---|---|
| `title` | required, ≤ 200 chars |
| `description` | optional, ≤ 4000 chars |
| `status` | `todo` · `in_progress` · `done` |
| `priority` | `low` · `medium` · `high` · `urgent` |
| `due_date` | optional `YYYY-MM-DD` |
| `page_id` | optional link; FK **ON DELETE SET NULL** |
| `completed_at` | set when a task becomes `done`, cleared when reopened. Enforced: `(status = 'done') = (completed_at IS NOT NULL)` |

### `page_links`
`(source_page_id, target_page_id)` derived from `slothboss://page/<id>` links in a page's content on every
save. Powers "Linked from" / "Links to". Links to deleted pages stay in the text but are not indexed.

### `settings`
Key/value: `ai.model`, `ai.endpoint`, `ai.timeout_seconds`, `ui.theme`. No secrets.

### `ai_actions`
Audit log of every AI proposal: type, validated payload, human-readable summary, status
(`proposed` → `applied` | `rejected` | `failed`, then optionally `undone`), result (created ids and the
`updated_at` the action produced), undo data (previous content or field values), error, model, timestamps.
Page text is only stored here when an action itself carries content (e.g. a drafted page).

### `search_index` (FTS5)

`kind`, `ref_id`, `title`, `body`. Maintained **only by triggers** on `pages` and `tasks`, so search can't
drift from the data. Archived pages are not indexed.

## Agent tables (migration 002)

Defined in [`contracts/schema/002_agent.sql`](../contracts/schema/002_agent.sql); behavior in [AGENT.md](AGENT.md).

| Table | Holds |
|---|---|
| `approved_folders` | folders the user explicitly approved for agent access (path, label) |
| `agent_runs` | goal, mode, planner id, folder snapshot, state + reason, plan JSON and version, approved plan version, budget and usage, artifacts JSON (inventory, duplicates, summaries, actions, created tasks, report ids), final report, pause/cancel control, undo time |
| `agent_steps` | one row per planned step and plan version: tool + version, validated arguments, risk, approval state, status, attempts, unique idempotency key, user exclusions, result, error, verification checks, timestamps |
| `agent_file_ops` | every filesystem side effect (create folder, move, create report file) with source/target, SHA-256, size, reason, status (`proposed → running → applied`, `excluded`, `failed`, `undone`, `undo_failed`) |
| `agent_events` | the activity log (state changes, approvals, tool results, warnings, recovery notes) |

Run states and step statuses are `CHECK`-constrained in SQL; allowed run transitions are enforced in code.
Backups (format v1) do not include agent runs or approved folders; restoring a backup keeps them as they are.

## Page document (`content_json`, version 1)

Schema: [`contracts/schemas/content.schema.json`](../contracts/schemas/content.schema.json).

```json
{"version":1,"blocks":[
  {"type":"heading","level":2,"spans":[{"text":"Open questions"}]},
  {"type":"todo","checked":false,"spans":[{"text":"Read the "},{"text":"terms","bold":true}]},
  {"type":"paragraph","spans":[{"text":"See "},{"text":"Background","link":"slothboss://page/0b0c…"}]}
]}
```

- Block types: `paragraph`, `heading` (level 1–3), `bulleted`, `numbered`, `todo` (`checked`), `quote`,
  `code` (text may contain `\n`).
- Span marks: `bold`, `italic`, `code`, `link`.
- Links are restricted to `http`, `https`, `mailto` and `slothboss://page/<uuid>`; anything else
  (`javascript:`, `file:` …) is dropped on parse.
- **Canonical form** (both clients must produce byte-identical JSON): keys in the order shown; `level`
  only on headings; `checked` always on todos and never elsewhere; span flags only when `true`; adjacent
  spans with identical marks merged; empty spans dropped.

### Markdown export rules
Pinned by [`contracts/fixtures/content/kitchen-sink.md`](../contracts/fixtures/content/kitchen-sink.md):
`#`/`##`/`###` headings · `- ` bullets · `1. 2. …` numbering restarting after any non-numbered block ·
`- [ ] ` / `- [x] ` todos · `> ` quotes · fenced code · `**bold**`, `*italic*`, `***both***`,
`` `code` ``, `[text](url)` · `\ * _ ` [ ]` escaped in text · consecutive list items separated by one
newline, everything else by a blank line · empty paragraphs omitted. Page export prepends `# Title`.

## Backup format (version 1)

Schema: [`contracts/schemas/backup.schema.json`](../contracts/schemas/backup.schema.json). One JSON file
with `format: "slothboss-backup"`, `formatVersion`, `schemaVersion`, `exportedAt`, `generator`, all pages
(including archived, with hierarchy and content) and all tasks (with page links). Settings and AI history
are not included.

**Restore rules**
- The whole file is validated before anything is written: format marker, supported versions, UUID ids,
  unique ids, existing parents, no cycles, valid documents, valid task fields and dates, task links to
  pages present in the backup. Any error rejects the file.
- Inconsistent completion data is repaired with a warning shown before confirmation.
- Two destinations: **a new workspace file** (nothing existing is touched), or **replace the current
  workspace** — after confirmation and after a safety snapshot (`VACUUM INTO`) is written next to it.
  Replacement is one transaction.
- Ids are preserved, so links and task references survive. Restoring into a non-empty workspace is always
  a full replace; merging is not supported.
